# NCViewer UI 设计审查

## 审查范围与目标

审查主窗口、数据树、元数据面板、绘图窗口及其空状态和时间滑块，目标是支持“打开数据集 → 浏览变量 → 查看元数据 → 双击绘图”的中文科研工作流。依据 product-design audit 与 design-qa 框架，覆盖视觉层次、间距与对齐、配色、字体排版、控件一致性、状态反馈、可访问性、布局合理性、图标和内容。

## 发现与建议

| 发现的问题 | 优先级 | 修改建议 |
| --- | --- | --- |
| 应用没有统一 QSS、字体、控件状态和焦点样式，Qt 默认风格导致视觉层次不稳定 | P1 | 在入口加载统一的 Microsoft YaHei 字体和低饱和蓝青配色，统一边框、圆角、选中态、悬停态和焦点态 |
| 未打开文件时右侧为空，用户缺少下一步提示 | P1 | 增加“请打开 NetCDF 文件”空状态，并在打开文件后切换为元数据内容 |
| 数据树只有文字，数据集、变量组、可绘图变量缺少类型线索；双击行为不明显 | P1 | 使用 Qt 内置标准图标区分节点，增加树标题和“双击绘图”工具提示/状态栏反馈 |
| 元数据采用单一扁平表单，维度、坐标、属性和时间信息难以扫描 | P1 | 使用分组标题组织“变量信息”“时间信息”“全局属性”，突出时间范围 |
| 主窗口和绘图窗口间距、默认尺寸、分栏比例未表达主要任务 | P2 | 设置合理最小尺寸、分栏初始比例、内容边距；绘图时间区加入当前值和播放占位按钮 |
| 菜单/工具栏缺少图标和中文 tooltip，操作反馈弱 | P2 | 使用 Qt StandardPixmap 图标，为打开、重置等操作增加中文提示，更新状态栏 |
| 时间滑块只有一行标签，缺少范围和当前切片摘要；绘图窗口没有状态栏摘要 | P2 | 增加时间区标题、当前时间值、范围标签、播放占位按钮和切片摘要状态栏 |
| 键盘焦点和高对比度状态未显式设计 | P2 | 为树、滑块、输入类控件提供清晰焦点环；前景/背景采用高对比中性灰与蓝青 accent |
| 现有中文可见文本基本完整，但窗口标题和菜单层级需要更一致 | P3 | 统一中文命名和信息语气，保留 NetCDF/NCViewer 等必要专名 |

## 结论摘要

1. 功能路径完整，但默认 Qt 外观无法体现“中文界面 + 现代 UI”的核心差异化。
2. 全局样式令牌、字体和状态样式是最高收益的基础改动。
3. 空状态和状态栏反馈需要补齐，降低首次使用的迷失感。
4. 数据树应通过内置图标和 tooltip 明确节点类型与双击绘图行为。
5. 元数据应按变量、时间、属性分组，并让时间信息形成视觉重点。
6. 主窗口需要更合理的最小尺寸、分栏比例和内容留白。
7. 绘图窗口的时间控制区需要当前值、范围、播放留位和切片摘要。
8. 已设置清晰焦点样式和对比色，但完整屏幕阅读器语义仍需真实环境进一步验证。

## 证据限制

本审查以现有 PySide6 代码和无头控件状态为依据；未在真实桌面环境完成鼠标/键盘录屏，也未宣称完整 WCAG 合规。需在 Windows 高 DPI、系统字体缺失和长中文属性值场景补充人工检查。
